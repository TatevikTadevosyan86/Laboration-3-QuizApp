# Test Report

## Summary

The application was tested manually through its interface and has one
automated score-storage test using Node's built-in test runner. The manual
cases cover nickname validation, avatar selection, profile persistence,
the four quiz activities, feedback, progress, results, and retry rounds.
Results marked as manually confirmed describe development checks before
the latest view refactoring; they are not evidence of a complete regression
run against the current source or published version.

The interface was refactored into PlayerSetupView, ActivityMenuView,
QuestionView, and ResultsView. LearningApp coordinates the quiz flow and
receives its dependencies from main.js. The post-refactoring regression
case T23 remains pending. Expected outcomes for the original requirements
have not changed.

To repeat the manual tests, open
https://tateviktadevosyan86.github.io/Laboration-3-QuizApp/ and follow the Input
column. Alternatively, run `npm ci`, `npm run build`, and `npm run preview`,
then open http://localhost:4173/Laboration-3-QuizApp/. Use a separate browser
profile without previous app data for score tests, and retain that profile
throughout persistence checks. Inspect Local Storage where specified.

Run `npm test` to repeat the automated test in `test/ScoreStorage.test.js`.
It substitutes MemoryStorage for browser localStorage, saves Counting scores
of 3 and 2 and a Letters score of 5, then reads them through a fresh
ScoreStorage instance. It checks latest/best values, completed-round counts,
and separation between activities. It does not test browser refresh,
retry exclusion, damaged data, or unavailable storage. On 2026-10-17, the
existing automated test passed (1 passed, 0 failed). Syntax checks also
passed for LearningApp, all four view classes, and main.js.

Offline caching and audio updates were the most involved parts to verify,
because a service worker can retain an older recording until an update
activates. Load online, wait for caching, reload online once, then select
Offline in developer tools and reload normally. Test activities and all
12 recordings, then restore the network setting. Do not use a hard reload
or the development server for this test.

Production builds passed during development, including a build after the
view extraction; a build does not replace interface testing. Offline
reload/audio were reported working, but the Sun instruction was heard as
Sunday. Its recording was replaced; listening confirmation and published/
offline retesting remain pending. An uncached favicon request also caused
an offline console error. Browser version, exact tested commit, and manual
test-session details were not recorded, so full deployed-site acceptance
has not been established.
